Selecionar registros com uma regra clara

SQL é a linguagem usada para consultar dados organizados em tabelas. WHERE funciona como uma peneira: mantém somente linhas cuja condição é verdadeira. AND exige condições simultâneas; OR aceita alternativas; NOT nega uma condição. Como AND tem precedência sobre OR, parênteses ajudam a expressar a regra de negócio sem ambiguidade. Na tabela fictícia PedidosEstudo, use WHERE Filial = 'A' AND (Status = 'Aberto' OR Status = 'Pendente'). Sem os parênteses, pedidos pendentes de outras filiais poderiam entrar.

LIKE busca padrões: LIKE 'Ana%' procura nomes iniciados por Ana. BETWEEN inclui os dois limites; IN verifica pertencimento a uma lista ou resultado de consulta. ALL exige que uma comparação valha para todos os valores do conjunto; ANY exige pelo menos um. Conjuntos vazios e valores desconhecidos pedem atenção: não trate esses operadores como sinônimos. Para datas com horário, um intervalo até a meia-noite pode deixar registros do último dia de fora.

Limitar e paginar não é filtrar

TOP limita a quantidade de linhas retornadas. Para solicitar os maiores valores, combine a limitação com ORDER BY, que define a ordenação. Sem isso, TOP não significa maiores nem mais recentes. Em valores empatados, acrescente um identificador único ao critério de ordenação quando precisar de resultado estável. OFFSET_FETCH permite pular linhas e buscar um lote seguinte; no SQL Server, essa construção acompanha ORDER BY. Pense nas páginas de um catálogo, mas lembre que alterações nos dados entre consultas podem deslocar registros mesmo com uma ordenação bem definida.

Ausência de informação e resumos

NULL representa informação ausente ou desconhecida; não equivale automaticamente a zero nem a texto vazio. Para localizar ausência, use IS NULL, não = NULL. Uma comparação comum com NULL produz resultado desconhecido, que WHERE não mantém. Um erro recorrente é usar NOT IN sobre uma lista contendo NULL e presumir que o resultado será o complemento intuitivo de IN. Primeiro esclareça como a regra deve tratar ausências.

Agregação transforma várias linhas em uma medida: COUNT conta, SUM soma, MAX e MIN procuram extremos, AVG calcula a média. COUNT(*) conta linhas; COUNT(Valor) conta valores não nulos. SUM e AVG ignoram entradas nulas: trocar ausência por zero muda o significado da análise. GROUP BY separa grupos antes de calcular seus resumos, como envelopes diferentes para cada filial. Em SELECT Filial, SUM(Valor) FROM PedidosEstudo GROUP BY Filial, cada filial recebe seu total. Selecionar uma coluna adicional sem agregá-la nem incluí-la no agrupamento costuma gerar erro. Esses fundamentos apoiam consultas em projetos ligados ao Protheus, sem pressupor tabelas reais ou autorizar alterações em produção.

SQL Server 2016 — Módulo 7 — WHERE e operadores lógicos
1. Você quer pedidos da filial A que estejam Abertos ou Pendentes. Qual condição expressa essa regra sem incluir pendentes de outras filiais?
Os parênteses agrupam as alternativas de status antes da combinação com a filial. Sem eles, AND tem precedência sobre OR e pedidos pendentes de outras filiais podem entrar. Referência: Módulo 7, Operadores lógicos e WHERE; confirme o exemplo da aula.
SQL Server 2016 — Módulo 7 — LIKE e BETWEEN
2. Uma consulta precisa de nomes iniciados por Ana e valores dentro de um intervalo inclusivo. Qual interpretação está correta?
O símbolo % aceita uma sequência de caracteres após Ana. BETWEEN inclui os limites inferior e superior; com datas e horários, o limite final precisa representar corretamente o período. Referência: Módulo 7, Operadores lógicos.
SQL Server 2016 — Módulo 7 — IN, ALL e ANY
3. Para um conjunto não vazio e sem NULL, como distinguir IN, > ALL e > ANY?
Pertencimento é diferente de comparação com todos ou com algum valor. A restrição do enunciado evita particularidades de conjunto vazio e NULL. Referência: Módulo 7, Operadores lógicos: IN, ALL, ANY.
SQL Server 2016 — Módulo 7 — TOP
4. Você pediu os pedidos de maior valor com TOP, mas não definiu ORDER BY. Qual diagnóstico é adequado?
É necessário ordenar por Valor em ordem decrescente para escolher os maiores. Um identificador único pode desempatar e tornar a seleção estável. Referência: Módulo 7, TOP.
SQL Server 2016 — Módulo 7 — OFFSET_FETCH
5. Ao paginar pedidos com OFFSET_FETCH, qual prática ajuda a evitar ambiguidades na ordem de registros empatados?
OFFSET_FETCH exige ORDER BY no SQL Server. Um desempate único define a ordem entre empates; alterações concorrentes ainda podem deslocar linhas entre páginas. Referência: Módulo 7, OFFSET_FETCH.
SQL Server 2016 — Módulo 7 — Trabalhando com NULLs
6. O campo DataPagamento está sem informação. Como localizar essas linhas sem confundir ausência com uma data ou texto vazio?
IS NULL testa ausência. A comparação = NULL não se torna verdadeira como uma igualdade comum, e WHERE descarta o resultado desconhecido. Referência: Módulo 7, Trabalhando com NULLs.
SQL Server 2016 — Módulo 8 — Funções de agregação
7. Uma tabela fictícia contém linhas com Valor preenchido e outras com Valor NULL. Qual afirmação permite conferir um relatório?
Contar linhas não é o mesmo que contar valores conhecidos. Ignorar ausência na média difere de tratá-la como zero; a regra do indicador precisa estar clara. Referência: Módulo 8, Funções de agregação: COUNT, SUM, MAX, MIN, AVG.
SQL Server 2016 — Módulo 8 — GROUP BY
8. Qual consulta representa o total de Valor por Filial na tabela fictícia PedidosEstudo?
GROUP BY reúne as linhas de cada filial e SUM calcula o total de cada grupo. Na primeira alternativa, Filial não foi agrupada nem agregada. Referência: Módulo 8, GROUP BY, com continuação prevista hoje.
