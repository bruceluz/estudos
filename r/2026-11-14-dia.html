Módulo 6 — relacionar sem perder o significado

JOIN é uma junção: combina linhas de tabelas, como conferir duas listas de fornecedores. FULL JOIN preserva as linhas dos dois lados, inclusive quando não existe correspondência. Nesse caso, as colunas do lado ausente aparecem como NULL, marcador de informação ausente, não como zero. Imagine duas listas fictícias: Cadastro tem códigos A e B; Contratos tem B e C. Unindo pelo código, aparecem A sem contrato, B associado e C sem cadastro correspondente. Isso ajuda a investigar divergências, sem provar automaticamente qual lista está correta.

Um erro comum é presumir que FULL JOIN elimina repetições. Se a chave usada na condição encontra várias linhas correspondentes, a junção pode multiplicar resultados. Antes de somar valores, confira a granularidade, isto é, o que cada linha representa. Um fornecedor pode ter vários contratos; código de fornecedor não identifica sozinho um contrato.

CROSS JOIN faz o produto cartesiano: combina cada linha de uma tabela com cada linha da outra, como montar todas as combinações de modelos e cores. Serve para gerar possibilidades, não para descobrir vínculos existentes. Em um laboratório fictício, combine categorias de produto e filiais para planejar uma matriz de cobertura. O erro seria interpretar cada combinação como venda realizada. Tabelas grandes também podem gerar resultados enormes; limite o exemplo e preveja as combinações antes de executar.

Módulo 7 — calcular, comparar e selecionar

Predicado é uma condição avaliada sobre os dados, como a regra de entrada de uma fila. Em SQL, pode resultar em verdadeiro, falso ou desconhecido quando há NULL. Um filtro WHERE conserva apenas condições verdadeiras. Esse detalhe se conecta às junções: filtrar depois uma coluna do lado ausente pode retirar justamente as linhas sem correspondência que você pretendia investigar.

Operadores aritméticos calculam valores; operadores de comparação verificam relações. Em PedidosFicticios, quantidade * preco representa um valor calculado, enquanto quantidade > 0 verifica uma condição. Não confunda comparação com atribuição nem suponha que toda divisão conserva casas decimais: no SQL Server, operandos inteiros produzem divisão inteira. Escolha tipos apropriados e use parênteses para tornar a intenção explícita.

AND exige ambas as condições; OR aceita pelo menos uma; NOT nega uma condição. Misturar AND e OR sem parênteses pode mudar o conjunto selecionado. LIKE procura padrões de texto; BETWEEN inclui os limites; IN verifica pertencimento a uma lista. ALL exige que a comparação seja verdadeira para todos os valores retornados pela subconsulta, enquanto ANY exige pelo menos um. Subconsulta é uma consulta usada dentro de outra. NULL pode tornar essas avaliações desconhecidas: não trate ausência como resposta negativa automática. Essa aula estava prevista apenas parcialmente ontem; confirme na aula até onde avançou.

SQL Server 2016 — Módulo 6 — FULL JOIN
1. Cadastro tem códigos A e B; Contratos tem B e C, uma linha por código. Um FULL JOIN pelo código preserva quais situações?
FULL JOIN preserva os dois lados. Linhas sem correspondência apresentam NULL nas colunas do lado ausente. Referência: Megacombo, SQL Server 2016, módulo 6, FULL JOIN; exemplo fictício próprio.
SQL Server 2016 — Módulo 6 — FULL JOIN e granularidade
2. Após uma junção, um fornecedor aparece em várias linhas porque possui vários contratos. Antes de somar um valor do cadastro, qual cuidado é adequado?
A granularidade é o que cada linha representa. Relações com várias correspondências podem repetir dados do cadastro e inflar somas. Referência: módulo 6, FULL JOIN; aplicação conceitual própria.
SQL Server 2016 — Módulo 6 — CROSS JOIN
3. Você precisa criar todas as combinações possíveis entre categorias fictícias e filiais para planejar cobertura. Qual operação corresponde a essa intenção?
CROSS JOIN combina cada linha de um lado com cada linha do outro. Essas possibilidades não comprovam vendas ou vínculos reais. Referência: módulo 6, CROSS JOIN.
SQL Server 2016 — Módulo 7 — Predicados
4. Uma condição de filtro avalia uma coluna que contém NULL. Qual entendimento evita tratar ausência como um valor conhecido?
SQL usa lógica com verdadeiro, falso e desconhecido. NULL indica ausência de valor, não zero nem texto vazio. Referência: módulo 7, Predicados; a aula de NULLs está prevista para hoje.
SQL Server 2016 — Módulo 7 — Operadores aritméticos
5. Uma consulta do laboratório divide dois valores inteiros, mas o resultado esperado precisava de fração. O que investigar primeiro no SQL Server?
Divisão entre inteiros produz resultado inteiro no SQL Server. Tipos e conversões precisam expressar a precisão desejada. Referência: módulo 7, Operadores aritméticos.
SQL Server 2016 — Módulo 7 — Operadores de comparação
6. Qual expressão verifica uma condição em vez de calcular o valor total de um pedido fictício?
O operador > compara valores. Multiplicação, adição e subtração produzem valores calculados. Referência: módulo 7, Operadores de comparação e Operadores aritméticos.
SQL Server 2016 — Módulo 7 — AND e OR
7. A regra fictícia exige filial SP e, dentro dela, pedido aberto ou pendente. Qual filtro expressa essa regra sem depender de uma leitura ambígua?
Os parênteses mantêm as duas opções de status subordinadas à exigência da filial SP. Na última alternativa, pedidos pendentes de outras filiais também poderiam entrar. Referência: módulo 7, Operadores lógicos; confirme o trecho previsto parcialmente ontem.
SQL Server 2016 — Módulo 7 — ALL e ANY
8. Comparando um preço com uma subconsulta não vazia que só retorna valores conhecidos, qual interpretação está correta?
ALL quantifica a comparação sobre todos os valores; ANY sobre pelo menos um. O enunciado exclui NULL e conjunto vazio para focalizar essa distinção. Referência: módulo 7, Operadores lógicos; confirme na aula o trecho efetivamente estudado.
