Agrupar não é apenas ordenar

GROUP BY reúne registros com a mesma chave para calcular resumos, como totais por fornecedor. Imagine separar recibos em envelopes: cada fornecedor tem um envelope. Em uma tabela fictícia Compras, com Fornecedor e Valor, SELECT Fornecedor, SUM(Valor) AS Total FROM Compras GROUP BY Fornecedor produz um total por fornecedor. SUM significa soma. As colunas selecionadas que não estão em funções de agregação, isto é, cálculos sobre conjuntos, precisam respeitar o agrupamento. Agrupar também não garante ordem de apresentação.

HAVING filtra os grupos depois da agregação. Para considerar apenas compras aprovadas antes de somar, use WHERE com a condição de aprovação; para selecionar fornecedores cujo total ultrapassa um limite, use HAVING sobre SUM(Valor). O erro comum é tentar colocar esse total diretamente no WHERE da mesma consulta. Pense na sequência lógica: escolher recibos, separar envelopes, somar, selecionar envelopes pelo total.

Consultas dentro de consultas

Subquery significa consulta interna. A self-contained é independente: pode ser compreendida e executada sem referência à consulta externa. Por exemplo, uma consulta interna calcula a média geral dos valores; a externa procura compras acima dessa média. Se a comparação exige um único número, a consulta interna precisa entregar um resultado compatível; várias linhas podem causar erro.

A correlated, ou correlacionada, depende de uma coluna da consulta externa. Exemplo conceitual: selecionar fornecedores para os quais existe compra aprovada, relacionando o identificador do fornecedor externo ao fornecedor da compra interna. Esquecer essa relação pode fazer uma compra de qualquer fornecedor validar todos. Essa dependência é lógica; não significa que o banco necessariamente executa fisicamente uma consulta separada para cada linha.

Escolher o operador pela pergunta

IN verifica pertencimento a um conjunto. EXISTS verifica se a consulta interna encontra alguma linha, não se ela retorna um valor específico. ANY pede que a comparação seja verdadeira para pelo menos um valor; ALL pede para todos. Em um conjunto não vazio e sem valores nulos, preço maior que ANY não equivale a preço maior que ALL. NULL representa informação ausente e exige cuidado: não trate desconhecido como zero, nem suponha que NOT IN se comporta como NOT EXISTS quando existem nulos.

Organizar e tratar texto

CTE, expressão de tabela comum, dá um nome a um resultado de consulta usado pela instrução seguinte, como uma etapa identificada de uma receita. Ajuda a separar agrupamento e filtragem para leitura; não cria automaticamente tabela permanente, índice ou garantia de desempenho.

No Módulo 10, LEFT e RIGHT extraem extremidades; SUBSTRING extrai um trecho; LEN mede comprimento, desconsiderando espaços finais no SQL Server; LOWER e UPPER mudam caixa; REPLICATE repete; REPLACE substitui; CONCAT combina textos. Um código fictício pode ter um prefixo extraído para um relatório. Erro comum: supor que transformar texto em uma consulta corrige o cadastro original.

SQL Server 2016 · Módulo 8 · GROUP BY
1. Uma consulta deve produzir um total de compras por fornecedor, sem detalhar cada compra. Qual estrutura corresponde ao objetivo?
GROUP BY define os grupos e SUM resume os valores de cada grupo. Ordenar não resume registros. Revise GROUP BY, Módulo 8 do curso SQL Server 2016.
SQL Server 2016 · Módulo 8 · HAVING
2. É preciso somar somente compras aprovadas e depois manter fornecedores com total acima de um limite. Como separar os filtros?
WHERE filtra linhas antes do agrupamento; HAVING filtra grupos, podendo usar agregações como SUM. Revise HAVING e GROUP BY, Módulo 8.
SQL Server 2016 · Módulo 9 · Subqueries self-contained
3. Uma consulta interna calcula a média geral das compras e não usa nenhuma coluna da consulta externa. O que caracteriza essa consulta interna?
Self-contained significa independente da consulta externa. A média geral pode servir como referência para uma comparação externa. Revise Subqueries self-contained, Módulo 9.
SQL Server 2016 · Módulo 9 · Subqueries correlated
4. Um EXISTS deveria selecionar fornecedores com compras aprovadas. A consulta interna procura compras aprovadas, mas não relaciona a compra ao fornecedor externo. Qual é o risco?
Sem a correlação, o teste deixa de perguntar sobre o fornecedor atual. Uma única compra aprovada pode satisfazer o EXISTS para todas as linhas externas. Revise Subqueries correlated e EXISTS, Módulo 9.
SQL Server 2016 · Módulo 9 · IN e EXISTS
5. Qual distinção descreve corretamente IN e EXISTS?
IN compara um valor com um conjunto. EXISTS testa a existência de linhas, não o conteúdo de uma coluna específica da projeção. Revise Operadores IN, ALL, ANY e EXISTS, Módulo 9.
SQL Server 2016 · Módulo 9 · ALL e ANY
6. Considere um conjunto não vazio de preços sem NULL. Um preço proposto supera alguns preços do conjunto, mas não todos. Qual afirmação é correta?
ANY exige ao menos uma comparação verdadeira; ALL exige todas. As condições sobre conjunto não vazio e ausência de NULL evitam outros casos de lógica. Revise ALL e ANY, Módulo 9.
SQL Server 2016 · Módulo 9 · CTE – Common Table Expressions
7. Uma CTE nomeia o resultado que resume compras por fornecedor. O que é correto esperar desse recurso?
A CTE organiza uma expressão de consulta para uso pela instrução seguinte. Não garante armazenamento separado nem desempenho superior. Revise CTE – Common Table Expressions, Módulo 9.
SQL Server 2016 · Módulo 10 · Funções de cadeia de caracteres
8. Um relatório precisa exibir o prefixo de um código e uma descrição em letras maiúsculas, sem alterar o cadastro. Qual abordagem atende ao objetivo?
LEFT extrai caracteres iniciais e UPPER converte letras para maiúsculas na expressão consultada. Um SELECT desse tipo não modifica o cadastro. Revise a aula de funções de cadeia de caracteres, Módulo 10; ela estava apenas iniciada no planejamento.
