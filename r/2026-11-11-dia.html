Organização e identificação — Módulo 3

Schema é um espaço de nomes dentro do banco, parecido com uma pasta organizadora. Em treino.Conta, treino identifica o schema e Conta, a tabela. Ele ajuda a organizar objetos e administrar permissões; não é outro banco nem uma cópia dos dados. Erro comum: imaginar que tabelas com o mesmo nome, mas schemas diferentes, são necessariamente o mesmo objeto.

Primary Key, ou chave primária, identifica cada linha de forma única e não aceita valores nulos. Pode reunir uma coluna ou várias. Na tabela fictícia Conta, ContaId pode ser a chave, enquanto Descricao é apenas uma característica. Duas contas podem ter descrições iguais sem serem a mesma conta. Erro comum: escolher uma descrição repetível como identificador. Uma tabela possui uma restrição de chave primária, mesmo quando ela abrange várias colunas.

Foreign Key, ou chave estrangeira, estabelece uma referência entre tabelas e protege a integridade referencial: impede referências não permitidas a registros inexistentes. Imagine Lancamento.ContaId apontando para Conta.ContaId. Um lançamento com conta preenchida precisa apontar para uma conta válida. A chave estrangeira pode aceitar nulo se a coluna permitir; ela não torna todo relacionamento obrigatório sozinha. Também não produz automaticamente uma consulta combinando tabelas. Erro comum: confundir relacionamento protegido com junção de resultados.

Identity é uma propriedade que gera números automaticamente ao inserir linhas, como um distribuidor de senhas. Não substitui a chave primária nem garante, sozinha, unicidade. Pode haver lacunas na numeração, inclusive depois de operações desfeitas. Portanto, não use a sequência como prova de quantidade de registros nem como numeração contábil obrigatoriamente contínua.

Inserção e criação — Módulo 4

INSERT INTO insere linhas em tabela existente. Declarar as colunas de destino explicitamente ajuda a conferir correspondência entre nomes, valores e tipos. Em laboratório fictício, primeiro cadastraríamos uma conta; depois, um lançamento referenciando essa conta. Tentar inserir o lançamento com referência inexistente pode violar a chave estrangeira. O comando precisa respeitar as restrições da tabela, não apenas apresentar sintaxe válida.

INSERT SELECT usa o resultado de uma consulta para inserir em uma tabela já existente. É útil para transferir um conjunto selecionado de lançamentos fictícios; as colunas precisam ser compatíveis. Repetir a operação sem critério pode duplicar dados quando não houver restrição que impeça isso.

SELECT INTO, cujo início estava previsto, cria uma nova tabela a partir do resultado de uma consulta e a preenche. Difere de inserir numa tabela preparada anteriormente. Não presuma que todas as chaves, índices e regras da origem serão reproduzidos: conferir essas estruturas é parte da validação. Regra prática: antes de inserir, explique destino, origem, colunas e restrições; para procedimentos específicos, confirme na aula.

SQL Server 2016 — Módulo 3 — Definição do schema
1. No laboratório fictício, treino.Conta e arquivo.Conta estão no mesmo banco. O que os prefixos indicam?
Schema organiza e qualifica objetos dentro do banco; não significa servidor separado nem cópia automática. Reveja Definição do schema, Módulo 3.
SQL Server 2016 — Módulo 3 — Primary Key (PK)
2. Duas contas fictícias podem ter a mesma descrição. Qual escolha representa melhor a função de uma chave primária?
A chave primária identifica cada linha sem duplicidade nem nulo; pode ser composta por várias colunas. Reveja Primary Key (PK), Módulo 3.
SQL Server 2016 — Módulo 3 — Foreign Key (FK)
3. Lancamento.ContaId possui chave estrangeira ativa para Conta.ContaId. A conta 777 não existe e um lançamento tenta referenciá-la. Qual comportamento é esperado?
Uma chave estrangeira protege a integridade referencial; não cadastra automaticamente o registro referenciado. Exemplo fictício. Reveja Foreign Key (FK), Módulo 3.
SQL Server 2016 — Módulo 3 — Campos Identity
4. Um colega encontrou lacunas em uma coluna Identity e concluiu que o banco está corrompido. Qual análise é adequada?
Identity gera valores automaticamente, mas não promete continuidade nem impõe sozinho unicidade. Não altere produção para eliminar lacunas. Reveja Campos Identity, Módulo 3.
SQL Server 2016 — Módulo 4 — INSERT INTO
5. Ao escrever uma inserção em uma tabela fictícia já existente, por que declarar explicitamente as colunas de destino?
Uma lista explícita ajuda a conferir nomes, ordem e tipos; as restrições continuam valendo. Reveja INSERT INTO, Módulo 4.
SQL Server 2016 — Módulo 4 — INSERT SELECT
6. Você quer inserir em ResumoTreino, tabela que já existe, linhas obtidas por uma consulta. Qual recurso corresponde a esse objetivo?
INSERT SELECT aproveita o resultado de uma consulta para inserir em destino existente; tipos e restrições precisam ser respeitados. Reveja INSERT SELECT, Módulo 4.
SQL Server 2016 — Módulo 4 — SELECT INTO
7. Em SQL Server, qual distinção é essencial entre SELECT INTO e INSERT SELECT?
SELECT INTO cria e preenche nova tabela; não presuma reprodução de todas as estruturas da origem. O calendário previa apenas o início dessa aula em 11/11. Reveja SELECT INTO, Módulo 4.
SQL Server 2016 — Módulos 3 e 4 — FK e inserção
8. Em tabelas fictícias com referência obrigatória de lançamento para conta, qual sequência respeita melhor a dependência?
A linha referenciada precisa existir quando a referência é verificada. Identity gera número; a chave estrangeira valida relação. Reveja Foreign Key e INSERT INTO.
