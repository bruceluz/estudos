Criar uma tabela e controlar identificadores

SELECT INTO cria uma tabela nova a partir do resultado de uma consulta, como copiar uma seleção de fichas para um arquivo novo. Em um banco inteiramente fictício, SELECT Codigo, Valor INTO ContasEstudo FROM ContasOrigem; cria ContasEstudo com as colunas selecionadas e seus dados. Não equivale a inserir linhas numa tabela já existente, nem a produzir uma cópia integral de toda a estrutura: índices, relacionamentos e outras regras não são simplesmente reproduzidos. Erro comum: tratar essa cópia como backup completo.

IDENTITY é uma propriedade que gera automaticamente valores numéricos para uma coluna. SET IDENTITY_INSERT permite, quando necessário e com as permissões adequadas, inserir explicitamente valores nessa coluna, como preservar números de fichas numa migração fictícia. É preciso indicar as colunas no INSERT; não significa desativar todas as validações. Na mesma sessão, apenas uma tabela pode ficar com essa opção ligada por vez. Termine desligando-a. Erro comum: supor que a opção evita colisões de chaves ou torna qualquer identificador válido.

Alterar, excluir ou esvaziar

UPDATE modifica valores de linhas existentes. Na tabela fictícia ContasEstudo, UPDATE ContasEstudo SET Valor = 120 WHERE Codigo = 7; busca alterar o valor da conta identificada. WHERE é a condição que delimita as linhas; sem ele, todas podem ser modificadas. Antes de pensar no comando de alteração, formule um SELECT com o mesmo filtro e confira quais registros seriam alcançados. Essa conferência reduz erros, mas não substitui controle de concorrência e transações.

DELETE remove linhas e admite WHERE; a tabela permanece. TRUNCATE TABLE esvazia a tabela inteira, sem filtro por linha, e reinicia o contador IDENTITY no SQL Server. Há restrições, inclusive relacionadas a referências por chaves estrangeiras. Não escolha TRUNCATE apenas por parecer mais rápido. Ambos exigem cuidado; em SQL Server, TRUNCATE pode ser revertido dentro de uma transação explícita ainda não confirmada. Transação é um conjunto de operações tratado como uma unidade. Não confunda essa possibilidade com recuperação garantida depois da confirmação.

Entender a consulta antes de abreviar nomes

Na ordem lógica simplificada de uma consulta, FROM identifica a origem, WHERE filtra linhas, SELECT define a saída e ORDER BY ordena o resultado. Isso ajuda a entender o significado da consulta; não descreve necessariamente a execução física escolhida pelo banco. Alias é um apelido temporário: SELECT Valor AS ValorConta FROM ContasEstudo; muda o nome apresentado, não renomeia a coluna armazenada. Um alias criado no SELECT normalmente não está disponível no WHERE da mesma consulta. Erro comum: confundir apelido de coluna com alteração da estrutura ou com alias de área de trabalho em AdvPL.

SQL Server 2016 — Módulo 4 — SELECT INTO
1. Você quer criar ContasEstudo, ainda inexistente, usando duas colunas de uma consulta fictícia. Qual descrição corresponde a SELECT INTO?
SELECT INTO cria a tabela de destino a partir da consulta. Não confunda cópia de dados selecionados com cópia integral de estrutura. Revisar: Megacombo, SQL Server 2016, Módulo 4, SELECT INTO.
SQL Server 2016 — Módulo 4 — SET IDENTITY_INSERT
2. Uma migração fictícia precisa preservar identificadores numa coluna IDENTITY. Para que serve SET IDENTITY_INSERT ON?
A opção permite valores explícitos na coluna IDENTITY; não elimina validações, permissões ou necessidade de listar colunas no INSERT. Revisar: Módulo 4, SET IDENTITY_INSERT.
SQL Server 2016 — Módulo 4 — UPDATE
3. Em laboratório fictício, o objetivo era alterar apenas a conta de Codigo 7, mas o UPDATE ficou sem WHERE. Qual é o principal risco?
Sem filtro, UPDATE não fica limitado à conta desejada. Primeiro confira os registros alcançados por um SELECT equivalente, sem tratar isso como proteção completa contra concorrência. Revisar: Módulo 4, UPDATE.
SQL Server 2016 — Módulo 4 — DELETE
4. Você precisa remover apenas contas fictícias marcadas como descartáveis e preservar as demais. Qual opção expressa a operação adequada?
DELETE permite selecionar linhas por condição, enquanto TRUNCATE não aceita WHERE. A tabela continua existindo. Revisar: Módulo 4, DELETE e TRUNCATE TABLE.
SQL Server 2016 — Módulo 4 — TRUNCATE TABLE
5. Qual previsão está correta ao estudar TRUNCATE TABLE no SQL Server, numa tabela de laboratório sem impedimentos?
TRUNCATE mantém a tabela, remove todas as linhas e reinicia IDENTITY. Existem restrições de uso; não é uma alternativa automática a DELETE. Revisar: Módulo 4, TRUNCATE TABLE.
SQL Server 2016 — Módulo 4 — TRUNCATE e transação
6. Um colega afirma: 'TRUNCATE nunca pode ser desfeito no SQL Server'. Qual correção é tecnicamente adequada?
SQL Server permite rollback de TRUNCATE dentro de uma transação apropriada ainda aberta. Não generalize para recuperação após COMMIT, a confirmação da transação. É um esclarecimento conceitual complementar à aula TRUNCATE TABLE.
SQL Server 2016 — Módulo 5 — Fases de processamento de uma consulta
7. Qual sequência representa uma ordem lógica simplificada útil para compreender uma consulta com filtro e ordenação?
Origem, filtro, projeção das colunas e ordenação formam essa sequência lógica simplificada. Não confunda ordem lógica com o plano físico de execução. Revisar: Módulo 5, Fases de processamento de uma consulta.
SQL Server 2016 — Módulo 5 — Trabalhando com Alias
8. Na consulta SELECT Valor AS ValorConta FROM ContasEstudo, o que acontece com ValorConta?
AS define um alias, ou apelido, para o resultado. O conceito nesta aula é SQL; não deve ser confundido automaticamente com alias de área de trabalho AdvPL. Revisar: Módulo 5, Trabalhando com Alias.
Matrizes — Curso de Algoritmos #15
9. Num exercício fictício, uma matriz organiza contas por linha e meses por coluna. O que é necessário para localizar uma célula específica?
Matrizes usam duas posições para localizar um elemento. A convenção inicial dos índices depende da linguagem ou ferramenta; confirme na aula. Questão conceitual associada ao título, sem atribuir exemplos ao vídeo indisponível.
